# Grabpic architecture and implementation reference

Documentation baseline: Windows 0.6.0, source tag [v0.6.0](https://github.com/talhazahid/grabpic/tree/v0.6.0). This document remains the Windows source reference. A native macOS implementation now lives in [macos/](../macos/README.md); [the macOS port plan](MACOS-PORT.md) tracks parity and open work.

## Process and window lifetime

`App` uses a user/session-local mutex plus a user-specific named pipe. A second invocation sends an action to the running instance. `ShutdownMode=OnExplicitShutdown` allows background operation with no visible window. Closing MainWindow hides it; Quit explicitly shuts down and disposes hooks and tray resources.

Commands accepted by the app include:

| Command | Meaning |
|---|---|
| No argument / `show` | Explicitly show app and recover latest capture |
| `background` | Run without showing main window |
| `full` | Full-screen capture according to monitor preference |
| `area` | Native rectangle selection |
| `folder` | Open capture folder |
| `settings` | Show Settings |
| `quit` | Ask running instance to exit |
| `browser:<path>` | Import a PNG only from the configured BrowserInbox directory |
| `--verify <report-path>` | Run Windows verification without normal UI startup |
| `--menu-enable`, `--menu-remove` | Standalone Windows menu helper actions; not portable |

The names describe Windows behavior. A macOS port may replace this command transport with local IPC and native application activation, preserving the user-facing intent.

## Native capture flow

1. MainWindow.BeginCapture rejects concurrent native captures, remembers pointer position, hides the main window, and briefly waits for it to disappear.
2. `Native.Capture` copies visible desktop pixels into a System.Drawing Bitmap. Full capture uses the monitor under the pointer or the virtual-screen union; area capture starts from the virtual-screen union.
3. AreaOverlay displays a frozen bitmap, uses a crosshair and physical pointer coordinates, and returns a selected rectangle. Escape cancels. Sub-2-pixel selections do not save.
4. Finish saves off the UI thread, remembers the saved path, copies to clipboard if enabled (with bounded retries), and updates the latest preview. It does not show the main window.
5. Explicit ShowApp loads a cached/recovered image asynchronously. A navigation generation prevents stale async work from replacing newer navigation.

The overlay uses retained DrawingVisual layers and frame-coalesced pointer updates, not full screenshot re-encoding on every pointer move. It requests WPF's default renderer (hardware eligible). The settings window explicitly uses software rendering as a compatibility workaround; do not carry that workaround into a new native renderer. Performance metrics represent selection-update/drawing submission times, not end-to-end display latency.

## Settings and persistence

Default profile: `%LOCALAPPDATA%\GrabPic` on the standalone Windows app. Store virtualization can redirect local state. `settings.json` is serialized from Preferences with case-sensitive property names; `latest-capture.json` is a separate JSON string containing the last saved absolute path.

| Property | Default / interpretation |
|---|---|
| `Folder` | Current user's Pictures directory + `Grab Pic` |
| `Organization` | `0` daily, `1` ISO week, `2` monthly |
| `Format` | `0` PNG, `1` JPG |
| `Quality` | `100`; JPG slider 40–100; PNG is lossless |
| `SettingsVersion` | Migration marker; versions below 1 migrate quality to 100 and save |
| `FullScreenShortcut` | Keyboard Ctrl+Shift+1 |
| `AreaShortcut` | Keyboard Ctrl+Shift+2 |
| `OpenCapturesShortcut` | Keyboard Ctrl+Shift+3 |
| `Monitor` | `0` monitor under pointer, `1` all monitors |
| `Copy` | `true` |
| `Watch` | `false`; optional clipboard-image monitoring |

A shortcut object has `Device` (`Keyboard` or `Mouse`), `Code` (Windows virtual-key or mouse-button number), and `Modifiers` (Alt=1, Ctrl=2, Shift=4, Win=8). Default Ctrl+Shift is 6. Mouse buttons: 1 left, 2 right, 3 middle, 4/5 extra buttons. These numeric key codes/flags are Windows-specific; do not interpret them as macOS key codes.

Date rules use the local capture time. Daily=`yyyy-MM-dd`; weekly=`ISO-week-year-Www`, including the ISO year at New Year; monthly=`yyyy-MM`. Filename shape: `Grab_yyyy-MM-dd_HH-mm-ss-fff_ab12.png` (or `.jpg`), with a random four-hex suffix. Preserve collision resistance; atomic unique-file creation would further strengthen it.

When the recorded latest path is missing, recovery scans the configured capture tree for PNG/JPG/JPEG files and selects the newest modification time. This scan can be expensive for large trees. Clipboard image monitoring uses Windows clipboard notifications plus a 220 ms debounce and sequence-number suppression of the app's own writes. Text clipboard contents are not saved.

Startup is managed outside this Preferences JSON: standalone Windows Run registration or packaged StartupTask/Windows settings. A macOS implementation should use a native login-item service, not migrate that registry state.

## Shortcut behavior

Ordinary combinations use RegisterHotKey. Explicitly assigned Windows-key combinations use a low-level hook so user-assigned Win+Shift+S can work while Grabpic is running. Repeats and corresponding key-up events are handled; quitting/clearing restores normal system behavior. The recorder uses temporary keyboard/mouse hooks so OS handlers do not steal the key before recording.

Reject modifier-only bindings, duplicates, malformed codes/modifiers, protected Win+L / Ctrl+Alt+Delete, and externally occupied ordinary shortcuts. Preserve the prior binding on registration/persistence failure. Global mouse shortcuts pause while Grabpic is focused. The implementation avoids consuming unmodified primary clicks globally. The macOS port must use its own reserved-shortcut and permission rules rather than promise that all Windows combinations can be intercepted.

## Browser capture flow and protocol

The browser background creates an HTTP/HTTPS context submenu: full scrolling page, visible view, area. A separate extension popup hosts a DOM canvas and progress UI. `activeTab`, `contextMenus`, `scripting`, and `nativeMessaging` permissions are requested; there is no permanent all-pages content script or network upload.

Full page injects a function into the top-level document to measure/scroll, pauses animation and smooth/snap scrolling, hides scrollbars during capture, hides repeated fixed/sticky elements after the first tile, captures PNG viewport tiles, and stitches horizontally/vertically. Last tiles crop clamped scroll overlap rather than overwrite earlier pixels. Original inline visibility and scroll position are restored in finally; a page-side 30-second inactivity watchdog attempts fallback restoration if the progress window disappears. Page size/layout/zoom/navigation changes and active-tab changes are rejected. The output is bounded to 60 million pixels and 32,700 pixels on each axis. Visible view uses the browser viewport API; area asks the app to show its native selector.

Native host name: `com.owl.grabpic`. Development Chromium extension ID: `fnnldbdenmkagpnfneogfcfnjpgjjdpl`, derived from the public key in Build-Browser.ps1. Firefox ID: `grabpic@owl.dev`. A future published store identity must be checked and its origin allowlist updated if different. The manifest public key is public metadata, not a signing secret.

Each message is UTF-8 JSON prefixed by a 4-byte unsigned/native-endian length (little-endian on the current x64 Windows host). Standard output is reserved for framed responses; logs belong on stderr. The console host handles one request per process.

| Request | Response / effect |
|---|---|
| `{"action":"ping"}` | `{"ok":true,"version":"0.6.0"}` |
| `{"action":"area"}` | Starts/contacts app, queues area selection; successful response acknowledges dispatch, not a completed image |
| `{"action":"image","data":"data:image/png;base64,..."}` | Validates PNG, writes a unique BrowserInbox PNG, starts/contacts app, waits for save receipt |
| Invalid request or failure | `{"ok":false,"error":"..."}` |

Image success responds `{"ok":true,"message":"Saved in your Grabpic capture folder."}`. The app imports through the same Finish path, deletes the temporary PNG after saving, and atomically publishes a `.result` receipt; the host reads/deletes the receipt. BrowserBridge waits up to 20 seconds for app command connection and another roughly 20 seconds for a save receipt. Failed transfers can leave temporary images for manual cleanup.

The Windows reader caps JSON at 96 MiB. **This does not override a browser transport limit.** Chrome's current documentation specifies 64 MiB from extension to host and 1 MB from host to extension. Base64 plus JSON adds overhead, so the 60-megapixel image limit does not guarantee successful transfer of a noisy image. A port should validate encoded length before sending, return an actionable error, and consider a separately versioned chunked protocol if needed. See [Chrome native messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging).

## Known limits and hardening opportunities

- Browser JavaScript is reusable; the Windows native host, registry setup, bitmap types, and IPC are not. Safari is not provided by these ZIPs.
- Full-page capture targets ordinary top-level scrolling documents, not arbitrary nested scroll panels, infinite feeds, virtualized lists, browser-internal pages, protected content, or PDFs. Video/animated content may change between tiles.
- Browser extensions need separate user installation/enabling and publication/signing. A website download does not bypass Chrome's Windows/macOS distribution restrictions.
- Current save receipts acknowledge local file saving; clipboard copying may still fail if the clipboard is busy. Preview/state errors after saving can cause a failed receipt despite a file already existing; review transactional behavior in the port.
- Native image validation currently decodes with System.Drawing before checking pixel count. A new host should inspect image metadata and enforce dimensions/bytes before expensive decoding, as well as validate allowed origins and file locations.
- A trusted same-user sender can send named-pipe commands. Inbox directory validation is present, but full symlink/reparse/TOCTOU hardening is not claimed; use safe file handling in the port.
- Native import rejects an import while another capture is active. The macOS port should make concurrency, queueing, acknowledgments, and cancellation explicit.
- Hidden virtual desktops are not captured. Multi-monitor HDR/color fidelity and every mixed-DPI layout are not fully verified.
- A previous interactive mouse regression did not complete. Do not describe all possible global mouse combinations as comprehensively tested.
- The v0.6.0 checks covered 18 Windows app assertions, Edge-based standards/quirks-mode stitching and pixel integrity, cancellation/tab-switch/oversize rejection, actual Edge extension load/menu registration, and an actual isolated native-host image save/receipt/cleanup. Firefox, independent Chrome interaction, macOS, and full Store-installed activation were not verified by those checks.
- The Store PC's certificate/sideload policy blocked local packaged-install testing. No trust or sideload settings were changed. Restricted capability approval and Store certification are not implied by a successful MSIX build.

## Build and QA entry points

Use the commands in [README.md](../README.md) and [STORE.md](STORE.md). The repo has no solution file requirement: build the csproj/project directories directly. Runtime assets are bundled during publish; Windows SDK tooling and the checksum-pinned Zig compiler are restored/downloaded by scripts.

| Variable | Purpose |
|---|---|
| `GRABPIC_PROFILE_DIRECTORY` | Isolate settings, latest capture, browser inbox, and instance mutex/pipe suffix for QA |
| `GRABPIC_SCREENSHOT_MODE=1` | Skip shortcut setup and browser registration for safe screenshots/isolated app QA |
| `GRABPIC_OVERLAY_METRICS` | File path for selection/renderer metrics; not an end-to-end latency benchmark |
| `GRABPIC_TEST_BROWSER` | Optional executable override for the Windows browser-stitching test |

Playwright tests expect Node + Playwright and currently contain Windows browser/native-host paths. Their fallback lookup references the original development runtime; use a normal installed `playwright` dependency and adapt launch paths on another machine. The test scripts are source examples, not a portable macOS test suite.

`dist/`, `submission/`, `artifacts/`, `reference/`, tool caches, bin/obj, and signing material are ignored. They are generated outputs or local research, not missing proprietary source. The ShareX research checkout is deliberately excluded; no ShareX source is linked into the app. Preserve [LICENSE](../LICENSE) and `packaging/Licenses/` notices.
